# Reflection

I drew the lines between the three tools around one question: does this step change anything, and does it make a judgement? The Data tool, `get_job_requirements`, only retrieves a job. I first planned to call it `analyze_job_requirements`, but "analyze" implied an evaluation, so I renamed it to keep retrieval separate from assessment. The Action tool, `save_skill_gap`, only validates and writes one entry. It never runs matching, so a bad save cannot hide inside an analysis, and its checks (an allowed gap type, a real candidate and job, a skill that belongs to that job, no duplicates, atomic writes) apply no matter who calls it. The Orchestration tool, `investigate_job_fit`, is where the real decisions happen. It labels each skill as a supported match, a possible match, a skill gap or missing evidence, and it saves only explicit gaps, because treating a skill that is absent from a CV as a gap is the exact mistake the project exists to avoid. The hardest boundary was the candidate profile. It is data, but a fourth tool would break the three-tool design, so the orchestrator loads it internally. The same tension came back when I added MCP annotations. An annotation describes the whole tool, so `investigate_job_fit` has to be labelled as a writer even though it only writes when `save_gap` is true. I handled this on the host side with an approval policy that looks at the arguments: read-only analyses run freely, and every save waits for the user.

Three tools covered the workflow cleanly. Each request maps to exactly one tool, and the agent routed correctly in every test, including direct Action calls. A fourth tool would only have been worth adding for candidate lookup, and that would have pushed the agent to chain calls the orchestrator already handles. The main limits are in the data: profiles are hand-written JSON, related skills are listed manually, and the plan is a local file. Useful next steps would be parsing real CVs into the profile format, pulling live job listings into the Data tool, exposing jobs and saved plans as read-only MCP resources, and tracking progress on saved development goals over time.
